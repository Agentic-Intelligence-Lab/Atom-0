配置百舸凭证：


检查代码环境、数据配置、norm 和 VLM 权重：

```bash
cd /data/wudi/Atom-0

PARAMS_PATH=/data/models/paligemma/pt_224.npz \

SA_FILTERED_RLDS_DATA_DIR=/data/wudi/RLDS_SA_Filtered \

.venv/bin/python scripts/preflight_cotrain_baige.py \

SA_FILTERED_RLDS_DATA_DIR=/data/wudi/RLDS_SA_Filtered \
PARAMS_PATH=/data/models/paligemma/pt_224.npz \
.venv/bin/python scripts/preflight_cotrain_baige.py \
  cotrain_full_all_sa_filtered
```

正式提交前确认：

- `/data/models/paligemma/pt_224.npz` 存在；
- `git status --short` 中没有未确认的代码改动；
- 每次新训练使用一个从未产生过 checkpoint 的 `EXP_NAME`。

如果复用已经存在 checkpoint 的 `EXP_NAME`，训练框架会恢复该实验自身的模型、
optimizer 和 step，而不会重新从 `PARAMS_PATH` 初始化。下面两条命令已经使用新的
VLM 实验名；再次重跑时，需要继续更换 `EXP_NAME`。

使用 VLM NPZ 时，任务启动日志应包含：

```text
PARAMS_LAYOUT=paligemma-vlm-npz
INIT_POLICY=PaliGemma vision+language loaded; action expert, timestep MLP, and action projections random
```

## 实验逻辑 

+ 正式训练1代表的是，只用真机数据，从paligemma开始训练。
同时，此实验配置也可以用来后训练微调。
即，如果是预训练后的模型想做真机微调，则修改正式训练1中的PARAMS_PATH，改成你的预训练ckpt，然后修改EXP_NAME，其他不变，进行训练即可。
这即完成了“直接训练” vs “预训练+微调”的对比

+ 正式训练2代表的是，如何用所有真机数据，从paligemma开始预训练

+ 正式训练3仅使用 State-Action 筛选后的自采 `piper30 + piper2`，
用于和正式训练1做可控对比。

+ 正式训练4使用保留原有主动排除策略、并经 State-Action 质量筛选后的新 RLDS，
采样权重和 norm 都以筛选后数据重新计算。

+ 进行新的实验时，需要修改EXP_NAME

+ 目前wudi分支的最新代码，已经修改了数据配置的代码，对于piper30数据集，已经自动切换至最新的validation set划分版本。

| FSDP devices | 4 |

## 正式训练 4：State-Action 筛选后的全量混训

该实验使用 `cotrain_full_all_sa_filtered`，包含自采真机、AgiBot、DROID、
EgoVerse、RoboCOIN 和 RoboMIND。它保留正式训练 2 及 full-all 配置原有的
5 个主动排除项，同时使用 State-Action 策略过滤 train episode；筛选后为空的
3 个 RoboCOIN builder 不加载。

| 超参 | 值 |
| --- | ---: |
| active datasets | 36 |
| train episodes | 300,589 |
| source frames | 243,049,603 |
| 动作空间 | Unified80 |
| 节点 × GPU | 3 × 8 B200 |
| FSDP devices | 4 |
| train global batch size | 1,536 |
| validation global batch size | 96 |
| train steps | 158,236（约 1 个 aggregate pass） |
| warmup / decay steps | 5,000 / 158,236 |
| peak / decay LR | `1e-6` / `1e-7` |
| eval / save interval | 1,000 / 25,000 |
| validation batches | 5 |
| action MSE | 关闭 |
| 初始化权重 | 基础 PaliGemma VLM |
| norm assets | `assets/cotrain_full_all_sa_filtered` |


```bash
cd /data/wudi/baige-cluster
export BOS_SOURCE=atom0-data/
export BOS_MOUNT_PATH=/mnt/bos/bo23lu
export SA_FILTERED_RLDS_DATA_DIR=/data/wudi/RLDS_SA_Filtered
export PARAMS_PATH=/data/models/paligemma/pt_224.npz

MODE=train CONFIG_NAME=cotrain_full_all_sa_filtered \
EXP_NAME=cotrain_full_all_sa_filtered_from_paligemma_vlm_b200_v1 \
INSTANCES=3 GPU_PER_NODE=8 FSDP_DEVICES=4 BATCH_SIZE=1536 VAL_BATCH_SIZE=96 \
NUM_TRAIN_STEPS=158236 WARMUP_STEPS=5000 DECAY_STEPS=158236 \
EVAL_INTERVAL=1000 SAVE_INTERVAL=25000 NUM_VAL_BATCHES=5 RUN_ACTION_MSE=0 \
DATA_NUM_PARALLEL_READS=1 DATA_NUM_PARALLEL_CALLS=2 WANDB_ENABLED=1 \
.venv/bin/python atom0_train_job.py
```

`/data` 以可写 PFS 挂载进入任务，因此新 RLDS 和新 norm assets 都能在训练容器中
按上述绝对路径访问。`SA_FILTERED_RLDS_DATA_DIR` 会由提交器显式转发给每个 pod。


## 任务检查

查询任务结构与日志：

```bash
cd /data/wudi/baige-cluster
.venv/bin/python logs.py <JOB_ID>
.venv/bin/python logs.py <JOB_ID> <POD_NAME>
```

启动后至少核对：

1. 日志中的 `PARAMS_LAYOUT` 为 `paligemma-vlm-npz`；
2. `EXP_NAME` 对应的 checkpoint 目录在提交前不存在；
3. W&B config 中 action dim 为 80；
4. 正式训练 1 构建了 `piper30` 和 `piper2` 的训练及验证 loader；
5. 正式训练 2 构建了 34 个 active datasets；
6. 正式训练 3 的 preflight 通过，并且只构建 `piper30 + piper2`；
7. 正式训练 4 的 preflight 通过，并构建 36 个 active datasets；
8. global batch、训练步数、warmup、decay、eval/save interval 与上表一致。
