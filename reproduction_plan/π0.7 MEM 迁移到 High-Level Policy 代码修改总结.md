# π0.7 MEM 迁移到 High-Level Policy 代码修改总结

日期：2026-06-04

## 0. 背景与动机（为什么要改）

此前的复现把 **long-term memory（语言记忆）的生成与监督直接塞进了 action 模型（π_LL / `Pi0`）**：
在 `pi0.py` 里加了 `compute_memory_summary_loss` / `generate_memory_summary_tokens`，并在训练时把
memory 的 CE loss 与 action 的 flow loss 合并（`total = flow + ki*ki_fast + w*mem_summary`），
推理时也由 action policy 自己生成 memory 并注入自己的 prompt。

经核对 **Physical Intelligence MEM 原文**（Torne, Pertsch, Walke et al., *MEM: Multi-Scale
Embodied Memory for VLAs*, π0.6-MEM, https://www.pi.website/download/Mem.pdf），上述实现与论文不符。论文把问题
**factorize 成两个独立 policy**（Section III-A）：

```
π(a, l_{t+1}, m_{t+1} | o_{t-T:t}, m_t, g)
  ≈ π_LL(a_{t:t+H} | o_{t-K:t}, l_{t+1}, g)        # 低层：只出动作，只消费 subtask
  · π_HL(l_{t+1},   m_{t+1} | o_t, m_t, g)          # 高层：联合生成 subtask + 长期记忆
```

关键结论：

- **long-term memory 由 high-level policy 生成**，且与 next subtask **一起**自回归生成。
- π_HL 与 π_LL 是**两个独立网络**（Fig.2：都是 SigLIP+Gemma；只有 π_LL 带 action expert），
  **分开训练**（高层文本 CE，低层 flow/FAST）。
- **π_LL 只消费 subtask `l_{t+1}`，从不直接看 memory**。
- memory 训练标签来自一个离线 LLM，把历史 subtask（含成功/失败）总结成 `m_t`，并压缩/删除过期信息。
- 短期视觉记忆（视频 encoder，每 4 层 temporal attention，只保留当前帧 token，无新增参数，
  sin/cos 使 t=0 为 0）与论文一致，**保留在 π_LL**。

因此本次迁移的目标：**把 long-term memory 从 action 模型搬到一个新的 high-level policy `Pi0HL`，
让 `Pi0HL` 联合生成 (subtask, memory)；π_LL 只消费 subtask、不再做任何 memory。**

已锁定的两个设计决策（用户确认）：
1. **合一**：subtask 与 memory 由同一个 `Pi0HL` 联合生成（忠实原文）。
2. **π_LL 只看 subtask，不看 memory**（忠实原文）。

## 1. 新增：High-Level Policy `Pi0HL`（Phase 1）

### `src/openpi/models/pi0_high_level_config.py`（新建）
`Pi0HLConfig`：无 action expert 的文本策略配置。
- `paligemma_variant="gemma_2b"`，仍构造一个 `action_expert_variant`（仅为复用 `[tokens, None]`
  双流调用约定，第二流永不喂 token，不参与前向）。
- `max_token_len=384`（prefix「Task+Memory」预算）、`memory_summary_max_len=128`（联合 target 预算）、
  `memory_generation_max_new_tokens`、`max_subtask_len`、`history_length` 等。
- `model_type → ModelType.PI0_HL`（见 Phase 4）。
- `inputs_spec`：images + state + `tokenized_prompt`（prefix）+ `memory_summary_*`（联合 target）。

### `src/openpi/models/pi0_high_level.py`（新建）
`Pi0HL(BaseModel)`：
- `embed_prefix`：images（+可选 state history）+ `Task: {g}\nMemory: {m_t}`。
- `compute_loss`：对联合 target「`Next subtask: {l}\nNew memory: {m_{t+1}}`」做 teacher-forced
  next-token CE（loss 只落在 target）。返回 `[b]` 数组。`actions` 入参被忽略。
- `generate`：greedy + KV-cache 解码联合文本（推理端按 `"New memory:"` 切分出 subtask / memory）。
- `sample_actions`：显式 `NotImplementedError`（π_HL 不出动作）。

### `src/openpi/models/tokenizer.py`（修改）
`PaligemmaTokenizer` 新增：
- `tokenize_high_level_prefix(prompt, memory_summary)` → `Task: {g}\nMemory: {m_t}\n`（→ `tokenized_prompt`）。
- `tokenize_high_level_target(target_subtask, target_memory_summary)` →
  `Next subtask: {l}\nNew memory: {m_next}`（causal + 全部计入 loss；→ `memory_summary_*`）。
- 辅助 `_pad_to_max`。

### `tests/mem/stage_hl_subtask_memory_overfit.py`（新建）
离线 forward + 单 batch overfit（dummy Gemma/SigLIP，不联网不下权重）。**已通过**。

## 3. HL 训练数据准备（Phase 3）

### `scripts/prepare_hl_data.py`（新建）
把**逐帧** memory/subtask 标注转成**逐帧** HL 训练表。核心：在每个 episode 内按
`memory` 字符串的连续相等性切段（segment = 长期记忆稳定的一段），然后逐帧派生：

- `target_subtask = l`、`target_memory_summary = m_{t+1}`（= 本段 summary）
- `memory_summary = m_t`（输入记忆）：段开头 `update_window` 帧用**上一段** summary（学 UPDATE；
  第 0 段用空串学 INIT），其余帧用本段 summary（学 KEEP）

输入支持：
- `--input` 逐帧 jsonl/json/parquet（列：`episode_index, frame_index, task, memory_summary[, subtask]`），或
- `--lerobot_root` 直接读 LeRobot 数据集（自动 `memory→memory_summary`，task 取自 `meta/tasks.jsonl`）。

输出 parquet 列：`episode_index, frame_index, task, memory_summary, target_subtask,
target_memory_summary, sample_kind`。

`--selftest` 离线逻辑校验**已通过**。

## 6. 使用方法

```bash
cd /export/pgs/xule/pi07_reproduction

# 1) 生成 HL 训练标签
.venv/bin/python scripts/prepare_hl_data.py \
  --lerobot_root /export/pgs/xule/lerobot/wudi/observe_and_pickup \
  --output /export/pgs/xule/lerobot/wudi/observe_and_pickup_hl_text.parquet

# 2) 训练 high-level policy（让 LeRobot 找到本地数据集）
export LEROBOT_HOME=/export/pgs/xule/lerobot
uv run scripts/train.py pi0_hl_rmbench \
  --exp-name=hl_observe_pickup_v1 \
  --data.hl_text_parquet=/export/pgs/xule/lerobot/wudi/observe_and_pickup_hl_text.parquet
```

逐帧标注（同事产出）要求：每帧一行，至少 `episode_index, frame_index, task, memory`（推荐含 `subtask`）；
**同一段稳定记忆内 `memory` 字符串必须完全一致**，术语稳定（脚本靠相邻帧是否相等自动切段）。
